# Supply chain review

## Stages

```
source -> build -> artifact -> distribution -> consumer
```

For each stage, name the control and the evidence. A claim without a verifiable
artifact is marketing.

## Source

- Branch protection, required review, signed commits if claimed.
- Dependencies pinned in a lockfile; registry configured; no git branch refs.
- Internal package names scoped to avoid dependency confusion.

## Build

- Build from the tagged commit, pinned toolchain, no mutable base image.
- No network fetch at build time unless pinned by hash.
- Secrets not available to the build unless needed; build secrets mounted, not
  baked into a layer.

## Artifact

- SBOM generated (SPDX/CycloneDX), includes transitive dependencies, attached to
  the release.
- Checksums published; artifact signed (Sigstore/cosign, GPG, platform).
- Provenance generated by the builder, not hand-written; SLSA level matches the
  actual build.

## Distribution

- Consumers verify the signature/checksum; instructions exist.
- No `curl | sh`, no mutable `latest`, no unverified redirect.
- Revocation process for a compromised release.

## Consumer

- Verification step documented and tested.
- Version pinning; update path; advisory subscription.

## Verdict

```
STAGE | control | evidence | gap
```

`CRITICAL` for an unsigned artifact presented as signed, or a build that fetches
mutable code; `HIGH` for a missing SBOM/provenance on a release. If there are no
findings, say `no findings` and list the stages you traced.
